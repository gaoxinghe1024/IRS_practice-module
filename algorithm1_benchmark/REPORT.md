# 算法一技术路线与课程评测报告

## 摘要

本实验针对 AnimeFinder 系统详情页的算法一“相似动漫推荐”建立离线评测。给定一部目标动漫，系统从完整目录中返回 Top-5 相似动漫。四种方法 A、B、C、D 统一使用 `genre`、`theme`、`demographic`、`studio`、`episodes` 五个字段，候选目录固定为 14,202 部作品，目标自身不参与推荐。

本版本使用固定随机种子生成 1,000 个合成测试目标。D 方法在该合成协议上的 `coverage@5` 为 **25.80%**，`NDCG@5` 为 **0.2855**，标准二值 `hit_rate@5` 为 **63.20%**，`precision@5` 为 **25.80%**。这里的 `coverage@5` 是 Recall@5，不等于“至少命中一个”的标准 `hit_rate@5`。

相关作品由单独声明的五维元数据 oracle 生成，不是 MAL 用户推荐或人工标注。参数在开发阶段试跑后校准，因此本结果用于可复现回归和受控方法比较，不能解释为真实用户准确率。

## 1. 项目目标

算法一的输入是一部动漫的稳定 MAL ID，输出 5 部相似动漫及其分数。该算法不读取登录用户、评分历史、收藏夹或聊天上下文，属于独立的知识型相似推荐模块。

本实验回答三个问题：

1. 五维知识属性能否在完整目录中产生可复现的相似动漫 Top-5？
2. A、B、C、D 四种方法在同一批 1,000 个目标上的排名质量如何？
3. 如何在统一指标、统一候选库和固定测试协议下复核结果？

## 2. 数据目录和字段投影

使用固定目录版本，共 14,202 部作品。每部作品投影成以下五个字段：

| 字段 | 数据含义 | 计算方式 |
|---|---|---|
| `genre` | 动漫类型集合 | 去重后计算 Jaccard |
| `theme` | 动漫主题集合 | 去重后计算 Jaccard |
| `demographic` | 目标受众标签 | 忽略大小写的精确匹配 |
| `studio` | 制作工作室 | 忽略大小写的精确匹配 |
| `episodes` | 集数 | `1 / (1 + abs(e1-e2) / 12)` |

两个空集合不产生标签相似度；空受众或空工作室不产生匹配；缺失或非正集数使用 0.5。标题、简介、评分、关系和用户历史不进入四种方法的推理输入。

## 3. 四种最终算法

### 3.1 A 固定五维加权

`A = 0.35 × genre + 0.30 × theme + 0.15 × demographic + 0.10 × studio + 0.10 × length`。A 不需要训练，五个分项可以直接解释给用户。

### 3.2 B 五维逻辑回归

B 使用同样的五维数值特征训练逻辑回归，排序分数为 `sigmoid(w^T x + b)`。本版本使用已冻结的优化模型，推理时只读取目录字段，不读取用户信息。

### 3.3 C 五维文本 BGE 语义相似

C 将五维字段组成固定文本，使用 `BAAI/bge-small-en-v1.5` 编码为 384 维 CLS 向量，再进行全目录均值中心化、L2 归一化和余弦相似度排序。

### 3.4 D 五维标签与语义融合

`D = 0.6 × A + 0.4 × semantic`。语义余弦使用固定的全目录 1% 和 99% 分位点映射到 `[0, 1]`，不按查询重新归一化。每个目标从除自身外的 14,201 个候选中排序，按分数降序、`anime_id` 升序稳定处理并列。

## 4. 测试集和合成真值协议

测试目标由目录 ID 的 SHA-256 稳定排序选择前 1,000 个，不按最终预测结果筛选。每个目标的 5 部相关作品由以下元数据 oracle 生成：

`0.50 × genre Jaccard + 0.30 × theme Jaccard + 0.10 × demographic exact + 0.10 × length similarity + N(0, 0.05)`。

`studio` 字段不进入 oracle。根据每个目标的固定随机数，候选池分为 easy（40%，池大小 8）、medium（40%，池大小 20）和 hard（20%，池大小 60），再按 oracle 分数以 temperature=0.035 加权无放回抽取五项。标签在模型排名计算前生成，生成器记录 seed、规则和目录哈希。

开发阶段先进行一次 exploratory 试跑，随后调整 oracle 权重、噪声和候选池参数再生成最终 1,000 条。因此最终结果可复现于当前协议，但不是预注册的独立估计。标签与五维输入同源，结果可能高于真实用户场景；当前发布数据用于回归测试，不承担 leakage-free holdout 或真实用户泛化结论。

## 5. 指标定义

设目标真值集合为 `T`，算法返回的 Top-5 为 `R5`：

| 指标 | 定义 | 解释 |
|---|---|---|
| `coverage@5` | `|R5 ∩ T| / |T|` | Recall@5；本报告的覆盖率口径 |
| `hit_rate@5` | Top-5 至少命中一项时为 1，否则为 0 | 标准二值命中率 |
| `NDCG@5` | 二值相关性，理想长度为 `min(5, |T|)` | 同时考虑命中位置 |
| `precision@5` | Top-5 命中数 / 5 | 每个目标最多返回 5 项 |

所有指标按目标宏平均。四种算法使用相同目标、相同真值和相同候选库，只比较最终排名指标。

## 6. 1,000 条测试集结果

四种算法均在同一批 1,000 个合成目标上评测。结果如下：

| 排名 | 方法 | 目标数 | coverage@5 | NDCG@5 | hit_rate@5 | precision@5 |
|---:|---|---:|---:|---:|---:|---:|
| 1 | A：固定五维加权 | 1,000 | **30.26%** | **0.3288** | **67.50%** | **30.26%** |
| 2 | D：标签与语义融合 | 1,000 | 25.80% | 0.2855 | 63.20% | 25.80% |
| 3 | B：五维逻辑回归 | 1,000 | 21.92% | 0.2371 | 54.90% | 21.92% |
| 4 | C：BGE 语义相似 | 1,000 | 13.54% | 0.1529 | 42.50% | 13.54% |

在当前合成协议下，A 的四项总体指标均高于 D，因此本 benchmark 不支持自动用 D 替换 A。D 仍可作为带有语义补充的候选路线，但不能把本次合成结果直接表述为 MAL 或真实用户效果。

## 7. 最终系统技术路线

### 7.1 推荐流程

系统加载 14,202 部目录、冻结的逻辑回归模型和 BGE 向量。收到目标 `anime_id` 后，计算五维特征、A/B/C/D 四路分数，排除目标自身，按稳定规则返回 Top-5。

### 7.2 输出字段

推荐接口返回 `anime_id`、`title`、`similarity` 和五维 `dimensions`。接口不需要用户 ID、评分历史或收藏夹状态。

### 7.3 复现命令

在 `algorithm1_benchmark` 目录执行：

```text
python generate_synthetic_1000.py --output results/synthetic_1000
python run_checks.py
python verify_delivery.py
```

结果目录包含 `testset.jsonl`、`ground_truth_used.jsonl`、`predictions.jsonl`、`per_query_metrics.jsonl`、`metrics.csv`、`summary.json` 和 `testset_manifest.json`。

## 8. 结果可信度和限制

合成 oracle 不是人工真值，且与五维输入存在结构关系；参数经过开发阶段试跑后校准，指标只适用于本协议。五维元数据无法表达剧情、画风、叙事、节奏和个人偏好，真实 MAL 推荐还存在用户群体、热度和长尾偏差。

本版本的 1,000 个目标用于代码稳定性、排序实现和受控方法比较。部署前应建立独立人工标注或真实用户离线集，预先固定抽样、真值、模型选择和替换门槛，并报告置信区间与分层结果。
