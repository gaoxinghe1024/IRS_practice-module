# results/ — file map

One line per file or directory: what it is, where the report uses it, how it
was produced. Generation is either the shipped replay tooling (`harness/`),
the judge tooling, or the team's offline analysis of the saved outputs
("offline analysis" below); every number is derived from the saved raw outputs,
never re-generated by a model.

## Top level

| Path | What it is / where used | Produced by |
| --- | --- | --- |
| `raw.jsonl.gz` | All saved model replies (R/N/T groups, 6 models x 80 queries + T); source for `--rescore` and for the contamination sensitivity | generation stage (saved verbatim) |
| `judge_raw.jsonl.gz` | All saved LLM-judge outputs; source for `python harness/judge.py --aggregate` and `--pairwise-matrix` | judging stage (saved verbatim) |
| `retrieval.jsonl` | Per-query retrieval output of the real `rag.py` pipeline (candidates, scenes, intent); used by the named-recall analysis (REPORT Appendix E) | parity run against the frozen pipeline |
| `scored.csv` | Per-reply rule + judge scores, final calibers; default replay input of `harness/analyze.py` | `python harness/analyze.py --rescore --write-scored` (`harness/score.py` + judge aggregation) |
| `tables/` | Report tables 1-8 (CSV + MD) | tables 1-2: `python harness/analyze.py --tables`; tables 3-8: offline analysis |
| `figures/` | Report figures fig1-fig4 (PNG + SVG) | `python tools/make_figures.py` (or `python harness/analyze.py --figures`) |
| `extra/` | Supporting analyses, per-question/per-reply tables, sensitivity checks (see below) | offline analysis |

## results/tables/

| Path | What it is / where used |
| --- | --- |
| `table1_main_results.*` | Headline per-model x group results (Model quality section); rows: T + 6 models x R/N; each metric has `mean`, `ci_lo`, `ci_hi` columns: scene `top1` (24 questions), `episode_ok` (22 scene questions with an episode check), `all_satisfy` (16), `inkb_rate` (80, reply level), `judge_avg` and `judge_all_avg` (80); generated from `results/scored.csv` by `python harness/analyze.py --tables` |
| `table2_by_type.*` | Key metrics per question type (Model quality section); long format `model, group, qtype, n, metric, mean, ci_lo, ci_hi`: scene `top1` / `episode_ok`; constraint `all_satisfy` / `per_work_rate`; similar `inkb_rate`; mood `mood_ok`; fact `fact_ok`; trap `rule_frank` (T10 excluded, n = 11); generated by `python harness/analyze.py --tables` |
| `table3_rag_lift.*` | R-N paired lifts with cluster-per-question bootstrap CIs (Key findings, Recommendations) |
| `table4_token_usage.*` | Token usage per model x group (Token usage section) |
| `table5_token_per_1k.*` | Tokens per 1k reply characters (Token usage section) |
| `table6_rag_token_delta.*` | R-N token deltas (Token usage section) |
| `table7_cumulative_usage.*` | Cumulative usage by stage (Token usage section) |
| `table8_retrieval.*` | Retrieval-layer metrics: intent trigger, Hit@1/3, constraint extraction (Retrieval layer section) |

## results/figures/

`fig1_grouped_bars.*` per-model judge score and reply-level in-KB citation
rate for N and R with 95% CIs (table 1), T as a dashed line; `fig2_rag_lift.*`
per-model R-N paired lifts (table 3; the in-KB row is the reply-level paired
difference from `scored.csv`); `fig3_quality_vs_tokens.*` judge score vs mean
net total tokens per answer (table 4), one arrow per model from its N point to
its R point; `fig4_threshold_sweep.*` scene-intent threshold sweep (System
issue 1). All four are rendered by `tools/make_figures.py` from packaged files
only (needs matplotlib).
