# data/

| Folder | In git? | Content |
|---|---|---|
| `raw/mal_2023/` | yes (Git LFS) | Kaggle `dbdmobile/myanimelist-dataset` files, unmodified (`anime-dataset-2023.csv`, `users-score-2023.csv`, optional `users-details-2023.csv`) |
| `enriched/` | yes | optional Jikan cache (`jikan/anime/<mal_id>.json`) and curated supplementary files (`relations.jsonl`, `characters.jsonl`, `reviews.jsonl`, `scenes.jsonl`, `scene_images/manifest.jsonl`) |
| `processed/<mode>/<version>/` | active version only (Parquet in Git LFS) | versioned output of `preprocess` (Parquet + reports + manifest) and the split manifests |
| `synthetic/` | yes | the seeded fictional world generated by `build-all --mode synthetic` |
| `evaluation/` | yes | human-provided evaluation / label files (`similarity_labels.jsonl`, `collection_events.jsonl`, `rag_queries.jsonl`, ...) |
| `evaluation/templates/` | yes | one example row per file format (never read by the pipelines) |
| `evaluation/human-evaluation-protocol.md` | yes | how to produce human labels and task-success records |

Field-level contracts: `docs/data-contracts.md`. Validate files with `python -m pipelines.cli validate-data`.

Getting the real data: the files are in the repository (Git LFS; run `git lfs pull` if they are pointers). To
start from a fresh download instead, get the Kaggle dataset `dbdmobile/myanimelist-dataset` (licence ODbL), put the
CSV files into `data/raw/mal_2023/`, run `make validate-real`, and after that the steps listed in
`docs/operations.md`.
Do not add `final_animedataset.csv`; it is not used.
